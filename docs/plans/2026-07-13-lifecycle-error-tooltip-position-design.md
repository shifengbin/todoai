# 生命周期脚本错误悬浮窗定位设计

## 问题

生命周期脚本错误悬浮窗在内容挂载前按固定最大高度估算位置。当失败状态靠近窗口底部且实际日志较短时，悬浮窗仍按约 320px 高度向上移动，因此与触发状态行之间出现明显空隙。

## 目标行为

- 保持现有 600ms 悬浮延迟和按需加载完整错误日志的行为。
- 悬浮窗以失败状态行为锚点，优先紧贴状态行下方显示，间距为 12px。
- 下方空间不足时，使用悬浮窗实际渲染高度紧贴状态行上方显示，间距仍为 12px。
- 横向位置与状态行左侧对齐，并限制在窗口左右 12px 安全边距内。
- 当上下空间都不足时，将悬浮窗限制在窗口安全区域内，内容继续通过现有最大高度和滚动条查看。

## 实现方案

悬浮开始时保留触发状态行元素，不再提前使用最大高度计算最终坐标。完整日志返回并使悬浮窗挂载到 `body` 后，在 Vue 下一次 DOM 更新中读取触发元素和悬浮窗的 `getBoundingClientRect()`，使用真实宽高计算位置。

悬浮窗完成测量前保持隐藏，避免短暂出现在窗口左上角。测量完成后写入固定定位坐标并显示。鼠标离开、状态失效、Retry 或 workspace 切换时继续沿用现有清理流程，同时清除锚点和已测量坐标。

## 测试

- 构造靠近窗口底部的失败状态行和实际高度较小的悬浮窗，确认上方坐标使用真实高度计算，而不是固定最大高度。
- 构造下方空间充足的状态行，确认悬浮窗位于状态行下方 12px。
- 保留现有延迟加载、Retry 清理、workspace 隔离和完整日志内容测试。
