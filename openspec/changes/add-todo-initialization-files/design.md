## Context

当前应用是 Go + Wails + Vue 桌面应用。TODO 任务文件夹位于当前 workspace 根目录下的 `tasks/<todo-dir>/`，在 TODO 进入 `in-progress`、打开任务终端或打开任务文件夹时创建或确保存在。任务文件夹目前自动维护系统生成的 `README.md`，README 会在 TODO 标题、描述、项目和分支信息变化后重新生成。

用户希望配置一组全局默认初始化文件模板。创建 TODO 时，系统展示这些模板，默认选择的模板自动勾选，非默认模板可手动勾选。TODO 创建后，当任务文件夹创建时，系统按用户选择写入同名文本文件。

## Goals / Non-Goals

**Goals:**

- 支持全局维护初始化文件模板，模板包含名称、描述、文件名、文本内容和默认选择状态。
- 创建 TODO 时展示模板名称、描述和文件名，并根据默认选择状态预勾选。
- TODO 创建时保存已选模板的文件快照，确保后续全局模板修改不影响已创建 TODO。
- 任务文件夹准备时写入选中的初始化文本文件，并继续生成 `README.md`。
- 防止准备流程覆盖用户已经在任务文件夹中修改或创建的同名文件。

**Non-Goals:**

- 不支持二进制文件、上传外部文件或目录递归复制。
- 不支持为已创建 TODO 重新同步全局模板内容。
- 不改变 `README.md` 的系统生成语义。
- 不实现任务文件夹自动清理或初始化文件删除同步。

## Decisions

1. **初始化文件模板存放在全局设置中。**

   选择：扩展现有 settings 持久化，增加 `todoInitializationFiles` 一类配置，并通过 Wails API 读取和保存。

   原因：初始化文件模板是跨 workspace 的用户偏好，和终端 shell、启动配置、主题类似，适合放在全局设置中。这样用户只需要配置一次，后续所有 workspace 的 TODO 创建表单都能使用。

   备选：把模板存放在每个 workspace 的项目状态中。该方案会让同一用户在不同 workspace 重复配置，不符合“全局默认配置”的需求。

2. **TODO 保存已选初始化文件的快照。**

   选择：扩展 TODO 数据模型或创建请求，在创建 TODO 时把选中的模板转成 `{name, description, fileName, content}` 快照保存到 TODO。

   原因：如果 TODO 只保存模板 ID，则全局模板后续修改会改变尚未进入 `in-progress` 的旧 TODO 行为，用户很难判断任务文件夹最终会得到什么内容。保存快照能让 TODO 创建时的选择成为稳定契约。

   备选：保存模板 ID 并在准备文件夹时读取最新模板。该方案适合“全局模板始终覆盖未来落盘内容”的语义，但和用户在创建 TODO 时看见并确认的内容不一致。

3. **任务文件夹准备时只写入不存在的初始化文件。**

   选择：`prepareTodoWorkspace`、`ensureTaskWorkspaceDir` 等任务目录准备路径在确保目录存在后写入初始化文件；若同名文件已存在则跳过。

   原因：任务文件夹创建流程可能被多条路径重复触发，且用户可能已经编辑过初始化文件。跳过已存在文件可以避免重复准备覆盖用户修改。`README.md` 继续由系统重生成，因为它是派生文件。

   备选：每次准备都覆盖初始化文件。该方案可以保证模板内容一致，但会破坏任务文件夹中用户对文件的手动修改。

4. **文件名只允许任务文件夹内的相对文件名。**

   选择：保存模板时校验文件名，禁止空文件名、绝对路径、路径穿越和目录分隔符；第一版只在任务文件夹根目录创建普通文本文件。

   原因：用户需求是“文件夹内创建文件名与设置相同的文本文件”。限制为根目录普通文件能避免写出任务文件夹、覆盖 worktree 子目录文件或引入复杂目录创建语义。

   备选：允许相对路径如 `docs/prompt.md`。这会提升灵活性，但需要额外处理目录创建、路径冲突和 UI 表达，第一版不需要。

5. **创建 TODO 表单只选择模板，不编辑模板内容。**

   选择：创建 TODO 表单展示模板名称、描述和文件名，并提供勾选；模板的新增、编辑、删除在设置界面完成。

   原因：创建 TODO 的核心流程应保持轻量。模板内容通常较长，放入创建表单会让表单复杂化。用户已要求创建时能看见描述和名称，并能勾选。

   备选：允许创建 TODO 时临时编辑内容。该方案会增加状态管理和快照差异展示，超出当前需求。

## Risks / Trade-offs

- [Risk] 全局设置文件变大，长文本模板会让 settings JSON 膨胀。→ Mitigation: 第一版仍使用 JSON，模板数量和内容体量预期较小；后续如出现性能或可维护性问题，再拆分为单独配置文件。
- [Risk] 同名模板文件被用户在任务文件夹中修改后，重新准备不会同步最新模板。→ Mitigation: 明确初始化文件是“创建时携带”，不是持续同步；README 仍作为系统生成文件持续更新。
- [Risk] 用户配置重复文件名并同时勾选，落盘结果可能不明确。→ Mitigation: 保存模板时校验文件名唯一，创建 TODO 时也对选中快照去重或返回明确错误。
- [Risk] 文件名包含路径穿越或平台非法字符可能导致安全或兼容问题。→ Mitigation: 后端保存和落盘前统一校验文件名，只允许任务文件夹根目录内的普通文件名。
- [Risk] 旧配置没有初始化文件字段。→ Mitigation: settings 加载时默认初始化文件列表为空，旧 TODO 的快照为空，迁移为无行为变化。
