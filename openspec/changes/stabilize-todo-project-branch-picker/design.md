## Context

当前应用在 TODO 创建、TODO 详情编辑、为 TODO 添加项目三个流程中为每个选中项目展示一个分支输入框。输入框使用原生 `datalist` 绑定 `ListProjectBranches(projectId)` 返回的所有本地和远端分支，用户既可以从候选中选择已有分支，也可以输入不存在的新分支。

这个实现满足了功能语义，但稳定性风险集中在前端：`datalist` 下拉由 WebView 原生实现，应用无法控制弹层渲染、候选数量或错误状态。大型仓库可能有数百到数千个远端分支，一次性渲染全部候选会放大 WebView 卡顿、内存峰值和闪退风险。

## Goals / Non-Goals

**Goals:**

- 避免原生 `datalist` 在大量分支候选下导致卡死或闪退。
- 保持用户可以选择已有分支，也可以手动输入新分支。
- 让分支候选加载失败或超时时不阻断 TODO 创建、编辑或添加项目。
- 复用现有 `ListProjectBranches` 和 TODO 提交 payload，不改变后端持久化语义。
- 用自动化测试覆盖大量候选、过滤候选和加载失败后的可用性。

**Non-Goals:**

- 不改变 Git worktree 创建规则。
- 不引入新的 UI 组件库或下拉依赖。
- 不实现远程分页搜索或 Git 后端模糊查询。
- 不自动 fetch 远端分支。
- 不改变用户输入不存在分支时从主分支创建新分支的语义。

## Decisions

### 用应用内受控候选弹层替换原生 datalist

选择：把分支字段抽象成应用内受控输入体验：输入框仍保存字符串，候选列表由 Vue 根据当前输入、已加载分支和显示上限渲染。用户点击候选时把候选值写回对应项目的 `baseBranch`。

原因：应用内弹层可以控制最大渲染数量、打开关闭时机、空状态和错误状态，避免把稳定性交给 WebView 原生 `datalist`。它也更容易测试，因为候选 DOM 和交互完全在 Vue 层。

备选方案：继续使用 `datalist`，只截断后端返回数量。该方案能降低 DOM 数量，但仍保留原生弹层兼容风险，也不能表达加载失败或候选被截断的状态。

### 候选过滤和渲染上限在前端完成

选择：`projectBranchOptions` 继续缓存完整分支列表，但实际展示候选时先按输入值做大小写不敏感包含过滤，再最多展示固定数量，例如 50 条。候选列表可以显示“继续输入以缩小范围”一类的轻量提示，但提交 payload 只使用输入框值。

原因：当前 `ListProjectBranches` 已经按项目缓存，Go 侧有 2 秒超时；在前端限制渲染量能以最小协议变更解决闪退风险。完整缓存也保留了用户输入后继续过滤的体验。

备选方案：修改后端 API 支持 query 和 limit。该方案更适合超大型仓库，但会扩大 Wails 绑定和测试范围。当前问题主要是前端一次性渲染/原生弹层风险，先在前端止血更直接。

### 分支加载失败不阻断手动输入

选择：分支加载失败时将该项目标记为加载失败或候选不可用，但分支输入框保持可编辑。表单提交仍按用户输入值生成 `projects: [{ projectId, baseBranch }]`。

原因：分支候选只是辅助选择，不是创建 TODO 或添加项目的硬依赖。后续 worktree 准备阶段已经会处理不存在分支、非 Git 仓库和 Git 不可用等情况。

备选方案：加载失败后禁用项目选择或表单提交。该方案会把辅助查询失败升级为业务阻断，用户无法通过手动输入绕过短暂 Git 查询问题。

### 三个入口复用同一套派生逻辑

选择：TODO 创建、TODO 详情、添加项目弹窗共用同一组分支候选状态和 helper，例如候选过滤、打开的候选菜单标识、选中候选、关闭候选、加载状态查询。

原因：三个入口当前已经共享 `projectBranchOptions`、`branchesForProject()` 和 `set...BaseBranch()` 形式的基础逻辑。继续复用可以避免其中一个入口仍保留 `datalist` 或候选数量不一致。

备选方案：先只修复用户报告最多的入口。该方案风险是同类闪退仍会在其它入口出现，且测试覆盖会分散。

## Risks / Trade-offs

- [Risk] 自定义候选弹层需要处理焦点、点击外部关闭和键盘行为。-> Mitigation: 首版保持交互简单，点击输入聚焦显示候选，点击候选选择，Escape/外部点击关闭；不在本变更中实现复杂组合框导航。
- [Risk] 前端仍会缓存完整分支列表，极端仓库的返回数据可能很大。-> Mitigation: 本变更先解决渲染和原生弹层风险；如仍有后端数据量问题，可后续增加 `ListProjectBranches` limit/query API。
- [Risk] 候选列表被限制后，用户可能看不到目标分支。-> Mitigation: 输入框支持任意输入，候选按输入过滤，用户继续输入即可缩小范围或直接提交。
- [Risk] 替换 `datalist` 会影响现有测试断言 `list` 属性和 `option` 元素。-> Mitigation: 更新测试为断言应用内候选项、候选上限和提交 payload，而不是原生 datalist 属性。

## Migration Plan

无需数据迁移。已有 TODO 工程副本中的 `baseBranch` 字段保持不变，后端 API 和持久化格式保持兼容。若需要回滚，可恢复原输入渲染逻辑，已保存数据不受影响。
