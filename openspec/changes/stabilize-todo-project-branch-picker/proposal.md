## Why

当前 TODO 关联项目时的分支控件依赖浏览器原生 `datalist`，并会一次性渲染项目的全部本地和远端分支。分支数量较多或桌面 WebView 原生下拉表现不稳定时，用户在选择项目分支时可能遇到卡死或应用闪退。

## What Changes

- 将 TODO 创建、TODO 编辑、为 TODO 添加项目中的分支选择体验稳定为应用内受控控件，继续支持选择已有分支和手动输入新分支。
- 限制候选分支的渲染数量，并按用户输入过滤候选，避免一次性把大量分支交给原生下拉或 DOM 渲染。
- 在分支列表加载失败、超时或不可用时保持表单可用，允许用户继续手动输入分支。
- 保留现有保存语义：提交后仍保存每个 TODO 工程副本的 base 分支，并用于后续 worktree 创建。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `todo-workspace`: 扩展 TODO 项目分支选择要求，明确分支控件在大量候选、加载失败和手动输入场景下必须保持稳定可用。

## Impact

- 前端：`frontend/src/App.vue` 中 TODO 创建、TODO 详情和添加项目弹窗的分支输入/候选渲染逻辑。
- 后端：`ListProjectBranches` 和 Git 分支列表查询语义保持兼容；如需要可增加候选上限或错误处理辅助，但不改变提交 API。
- 测试：补充前端回归测试，覆盖大量分支候选、候选过滤、加载失败后手动输入和三个分支选择入口。
