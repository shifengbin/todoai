## Context

TODO 工作区顶部包含两层控制：三段状态切换栏，以及开放 TODO 视图专用的排序/批量展开收起工具栏。当前 `未执行` 和 `执行中` 会渲染工具栏，`已完成` 因不是开放视图而移除该工具栏，导致用户点击 `已完成` 后顶部 workspace 区域高度变窄。

用户明确要求：切换到 `已完成` 时高度要和 `未执行`、`执行中` 一样，同时不要改变顶部状态切换栏宽度。

## Goals / Non-Goals

**Goals:**

- 保持 `未执行`、`执行中`、`已完成` 三个 TODO 状态视图的顶部控制区高度一致。
- 保持顶部三段状态切换栏宽度分配不随视图切换改变。
- 继续让开放 TODO 专用操作只在 `未执行` 和 `执行中` 中可见、可交互。
- 用组件测试或样式测试覆盖 toolbar 占位和 tabs 宽度规则。

**Non-Goals:**

- 不为 `已完成` 视图新增排序、批量展开或批量收起功能。
- 不改变 TODO 列表内容、完成历史排序或工作流状态语义。
- 不调整侧边栏整体宽度、拖拽宽度范围或终端区域宽度。

## Decisions

1. 保留一个统一的 TODO toolbar 容器。

   通过让 toolbar 容器在三个状态视图中都存在，并只在开放视图中渲染实际控件，可以稳定顶部高度，同时避免让 `已完成` 拥有不适用的操作。

   备选方案是在 `已完成` 列表上方添加 margin/padding。该方案能补高度，但语义上把布局补偿散落到内容区，后续 toolbar 高度变化时更容易失配。

2. 不改变 `.todo-view-tabs` 的三列布局。

   状态切换栏当前使用三等分 grid。保持这个规则不变，可以满足“不改变顶栏宽度”的要求，也避免在窄侧栏下出现某个状态按钮被挤压或重新分配宽度。

3. `已完成` 中的 toolbar 占位不应暴露可聚焦控件。

   如果使用隐藏控件作为占位，应避免它们进入键盘焦点顺序或被辅助技术当作可操作入口。更稳妥的实现是空的布局占位，或对内部控件使用不渲染而保留外层固定高度。

## Risks / Trade-offs

- 空 toolbar 占位可能看起来像多余空白 → 该空白只用于和开放视图顶部高度对齐，避免列表跳动。
- 固定/最小高度需要和现有 32px 控件高度保持一致 → 使用 CSS 变量或现有 toolbar 控件高度作为单一来源，减少未来失配。
- 测试环境不计算真实布局高度 → 组件测试可验证 DOM 和 CSS 规则；必要时补充浏览器/手工验证点击三个状态视图无高度变化。
