## Context

当前前端在 `App.vue` 中将终端拆分为 `workspaceTerminals` 与 `sidebarTerminals`：非全局终端传给 `ProjectSidebar`，全局终端则在主终端区域顶部渲染独立标签组。该标签组占用 xterm 的垂直空间，也使全局终端的活动状态与 TODO 侧栏中的终端树分离。

后端已经通过 `ProjectTerminal.workspaceTerminal`、workspace 专用终端上下文键以及现有创建、选择、删除 API 完整区分全局终端。选择全局终端时，后端会更新活动终端，但保留当前真实 TODO、TODO project、项目和 Git 状态上下文。本变更只重新组织前端展示，不需要迁移数据或改变 Wails 绑定。

TODO 侧栏已有真实 TODO 的状态筛选、排序、拖拽、展开状态、终端活动聚合和父子选中反馈。虚拟节点需要复用其中的视觉与交互语义，但不能进入真实 TODO 数据及其持久化流程。

## Goals / Non-Goals

**Goals:**

- 在 `执行中` 视图首位以单个 `Global 终端` 虚拟 TODO 展示全部 workspace 全局终端。
- 移除主终端区域顶部的 Global 标签组，让 xterm pane 使用完整可用高度。
- 复用真实 TODO 的展开、收起、批量操作和活动聚合反馈。
- 保持虚拟节点与真实 TODO 排序、拖拽、状态动作和持久化严格隔离。
- 保留现有全局终端生命周期、活动确认状态以及真实项目上下文语义。
- 让成功创建的全局终端立即在侧栏可见，同时保证失败时不产生乐观 UI 状态。

**Non-Goals:**

- 不创建真实或系统保留的 TODO 记录。
- 不改变 `ProjectTerminal`、项目状态文件、终端历史或 TODO UI 状态文件格式。
- 不改变全局终端的工作目录、shell 生命周期、恢复逻辑或 Wails API。
- 不为虚拟 TODO 增加优先级、完成、编辑、删除、状态流转或独立持久化能力。
- 不重新设计真实 TODO、项目终端或任务级终端的树结构。

## Decisions

### 1. 在 ProjectSidebar 中渲染专用虚拟节点

`App.vue` 继续计算带活动关注状态的 `workspaceTerminals`，并通过独立 prop 传给 `ProjectSidebar`。`sidebarTerminals` 仍只包含非全局终端。`ProjectSidebar` 在 `todoView === 'in-progress'` 且全局终端非空时，在真实 TODO 的 `v-for` 之前渲染专用虚拟节点。

虚拟节点不加入 `props.todos`、`currentOpenTodos`、`activeTodoIds` 或手动顺序数组。这样优先级排序、时间排序、手动排序、拖拽保存和 TODO 状态动作天然只处理真实 TODO。手动模式下虚拟节点不显示拖拽手柄，真实 TODO 的可拖放容器从虚拟节点之后开始。

备选方案是向 `currentOpenTodos` 注入带保留 ID 的伪 TODO。该方案能复用部分模板，但会要求所有编辑、状态、菜单、排序、拖拽和持久化路径识别并排除伪对象，遗漏风险高。另一备选方案是在后端创建特殊 TODO，会破坏全局终端不属于 TODO 的现有模型，因此不采用。

### 2. 保持主终端 pane 与侧栏导航解耦

`App.vue` 删除主终端区域的 Global 标签组、`has-global-terminals` 布局分支以及仅供该标签组使用的标签和删除控件。所有终端的 xterm pane 仍由现有 `terminals` 集合统一渲染和激活，终端管理器的输入、输出、resize、复制、粘贴、历史重放和自动重启流程保持不变。

顶部 `Global terminal` 按钮始终保留，用于在虚拟节点尚不存在时创建首个终端。虚拟节点 header 再提供一个新增入口，便于用户在侧栏继续创建终端。终端子项提供删除入口，并向 `App.vue` 发出终端 ID；选择、创建和删除继续调用现有 App handler。

### 3. 用通用函数聚合终端活动状态

现有 `todoActivityState(todo)` 通过 `todoId` 从侧栏终端中筛选后计算聚合状态。实现时提取一个接收终端集合的通用聚合函数，优先级保持 `needs-input > needs-ack > busy > idle`。真实 TODO 先筛选自己的终端再调用该函数，虚拟 TODO 直接传入 `workspaceTerminals`。

虚拟 TODO 展开时由终端子项分别显示活动状态；收起时才在父行显示整行呼吸反馈，规则与真实 TODO 一致。当前活动终端属于 `workspaceTerminals` 时，虚拟父项和对应终端子项显示选中状态；该状态完全由 `activeTerminalId` 推导，不写入 `activeTodoId` 或任何 UI 状态文件。

### 4. 为虚拟节点维护独立的会话内展开状态

`ProjectSidebar` 使用独立布尔状态保存虚拟节点是否展开，默认展开，不复用真实 TODO ID 集合，也不新增持久化字段。全局终端数量增加时将该状态设为展开，以保证顶部按钮或侧栏按钮创建的新终端可见。

`执行中` 视图的批量展开和收起会同时更新真实 TODO 与虚拟节点。真实 TODO 拖拽开始时，拖拽快照额外记录虚拟节点展开状态并临时收起；拖拽完成、取消或保存失败时，与真实 TODO 一起恢复快照。虚拟节点本身不进入拖拽 ID 或保存请求。

### 5. 创建成功后再切换视图

`createWorkspaceTerminal` 先调用现有后端 API。只有后端成功返回并应用新状态后，前端才通过现有 TODO 视图更新与持久化路径切换到 `in-progress`。全局终端数量增加会触发虚拟节点展开，随后现有活动终端激活流程挂载、适配并聚焦新 xterm。

若创建失败，catch 分支仅显示现有错误提示，不修改 `currentTodoView`、虚拟展开状态、活动终端或终端列表。选择和删除同样以成功返回的后端状态作为唯一数据源，不做提前移除或选中的乐观更新。

### 6. 复用侧栏视觉规则并保持动作隔离

虚拟 TODO header 复用真实 TODO 的行高、展开控件、双击折叠、选中背景和活动反馈样式，但不渲染优先级、状态动作、上下文菜单或拖拽手柄。全局终端子项复用现有终端行的名称回退、活动标记、键盘选择和焦点反馈，并增加明确的删除按钮辅助文本。

删除最后一个全局终端后，基于空数组的条件渲染会自然移除虚拟节点及其选中反馈；顶部创建按钮继续存在。切换到 `未执行` 或 `已完成` 仅隐藏虚拟节点，不停止或改变后台全局终端。

## Risks / Trade-offs

- [虚拟节点与真实 TODO 模板逐渐产生视觉差异] → 复用现有 CSS token、终端行辅助函数和活动聚合函数，只为虚拟节点保留必要的专用结构。
- [批量折叠或拖拽恢复遗漏虚拟展开状态] → 将虚拟展开状态加入同一批量操作和拖拽快照测试矩阵，但不加入排序 ID。
- [创建成功后视图切换触发额外 UI 状态保存] → 复用现有 todo view 更新队列，不新增独立写入路径；后端创建失败时不触发保存。
- [移除顶部标签组后活动 xterm 尺寸未及时更新] → 保留现有激活与 resize 适配流程，并在 App 集成测试中验证 pane 仍挂载且活动终端可重新 fit。
- [全局终端被误当作真实 TODO 上下文] → 所有父级选中状态均从 `workspaceTerminal` 和 `activeTerminalId` 推导，禁止创建伪 TODO ID 或修改真实上下文字段。

## Migration Plan

1. 先扩展 `ProjectSidebar` 的 prop、事件、虚拟节点、活动聚合和展开状态，并用组件测试固定行为。
2. 再由 `App.vue` 传入全局终端并接入创建、选择、删除事件，同时移除主终端区标签组及其样式。
3. 更新 App 集成测试，确认创建成功后的视图切换、失败回滚、上下文保持和 xterm pane 布局。
4. 运行前端测试和构建验证。由于没有数据格式或后端 API 变更，无需迁移用户数据。

回滚时可恢复主终端区 Global 标签组并停止向侧栏传递独立 prop；现有后端终端记录和历史无需转换。

## Open Questions

无。虚拟节点的数据归属、空状态、排序位置、展开行为、选择上下文和创建后视图切换均已确认。
