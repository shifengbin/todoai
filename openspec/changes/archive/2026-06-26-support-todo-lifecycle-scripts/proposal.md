## Why

TODO 启动和完成时经常需要执行固定的准备或收尾动作，例如生成环境文件、安装依赖、清理临时资源或同步结果。当前系统只能在 TODO 工作目录中写入初始化文件，无法为这些生命周期动作提供可复用、可选择、可重试且不阻塞 UI 的脚本自动化能力。

## What Changes

- 在全局管理菜单中新增“脚本管理”，用于维护成对的 TODO 初始化脚本和完成脚本模板。
- 每个脚本对包含名称、描述、初始化脚本、完成脚本和默认选择标记。
- 创建 TODO 时支持从脚本对下拉列表中筛选和选择，也可以不选择；选择项的描述用于帮助用户判断用途。
- TODO 保存创建时选择的脚本对快照，后续全局模板修改不影响已创建 TODO。
- 点击开始后 TODO 立即进入进行中，并在 TODO 工作目录中异步执行初始化脚本。
- 点击完成后异步执行完成脚本，并在脚本执行成功后完成 TODO；未选择完成脚本时沿用当前完成行为。
- 脚本执行不阻塞 UI；运行中显示状态，成功后不显示，失败时显示失败状态和重新触发入口。
- 软件在 Windows、macOS 和 Linux 上都支持脚本管理、选择、后台执行、状态展示和失败重试；脚本内容不做跨平台自动转换。

## Capabilities

### New Capabilities

- `todo-lifecycle-scripts`: 管理 TODO 生命周期脚本对，并在 TODO 开始和完成阶段异步执行、展示失败状态和支持重试。

### Modified Capabilities

- 无

## Impact

- 后端设置模型需要持久化全局脚本对模板，并提供加载和保存 API。
- TODO 数据模型和创建请求需要保存选中的脚本对快照。
- TODO 生命周期 API 需要调度后台脚本执行，并向前端发布执行状态事件。
- 脚本执行器需要在当前系统可用 shell 中运行脚本，并确保 Windows 后台执行不弹出控制台窗口。
- 前端需要新增脚本管理界面、创建 TODO 时的脚本选择控件、TODO 行/详情中的运行和失败状态展示，以及失败重试操作。
- 需要覆盖设置持久化、TODO 快照、异步状态、失败重试、完成脚本门控和跨平台执行参数的测试。
