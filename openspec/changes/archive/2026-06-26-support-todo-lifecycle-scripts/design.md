## Context

当前应用已经有三块相关能力：全局设置中保存终端 shell、启动配置和 TODO 初始化文件模板；创建 TODO 时可把初始化文件快照保存到 TODO；TODO 进入进行中时会准备 `tasks/<workspaceDirName>` 工作目录，完成时会归档 TODO 并清理关联上下文。

生命周期脚本需要横跨设置、TODO 创建、TODO 状态流转、后台进程执行和前端状态展示。它不能阻塞 Wails 调用或 Vue UI，也不能依赖嵌入式终端可用，因为 Windows 上嵌入式终端可能不可用，但后台命令仍应可执行。

## Goals / Non-Goals

**Goals:**

- 支持用户在全局管理中维护 TODO 生命周期脚本对。
- 支持创建 TODO 时从脚本对下拉列表中筛选和选择，也允许不选择。
- 将创建 TODO 时选中的脚本对保存为 TODO 快照。
- 点击开始后立即进入进行中，并异步执行初始化脚本。
- 点击完成后异步执行完成脚本，完成脚本成功后再归档 TODO。
- UI 只展示运行中和失败状态；成功状态不长期展示。
- 失败状态可重试，并在重试成功后清除。
- Windows、macOS 和 Linux 都能管理和执行脚本；脚本内容不做跨平台自动转换。

**Non-Goals:**

- 不提供脚本内容跨平台翻译或兼容性检查。
- 不把生命周期脚本输出渲染为完整终端会话。
- 不实现脚本取消、超时配置或并发队列管理 UI。
- 不支持一个 TODO 选择多个脚本对。

## Decisions

### 1. 脚本对保存为全局模板，TODO 保存快照

新增 `TodoLifecycleScriptTemplate` 到全局 settings，字段包含 `name`、`description`、`initScript`、`completeScript`、`defaultSelected`。创建 TODO 时保存为 `TodoLifecycleScriptSnapshot`，而不是只保存模板 ID。

理由：这延续 TODO 初始化文件的设计，避免用户修改全局脚本后改变已创建 TODO 的行为。备选方案是按 ID 引用全局模板，但那会让历史 TODO 行为不可预测。

### 2. 单选脚本对，最多一个默认项

创建 TODO 使用可筛选下拉选择一个脚本对，也可以为空。脚本管理保存时最多允许一个默认项；打开创建表单时自动选中默认脚本对。

理由：用户描述的是“脚本成对存在”和“下拉筛选”，这更接近单选配置。多选会引入执行顺序、局部失败和重试范围等额外复杂度。

### 3. 初始化脚本不阻塞 TODO 进入进行中

`ChangeTodoStatus(todoID, in-progress)` 保持快速返回：先完成状态流转和工作目录准备，再调度初始化脚本后台执行。初始化失败不会把 TODO 回滚到未开始，只在 TODO 上显示失败状态并提供重新执行。

理由：用户明确要求“初始化没完成也要到进行中”。脚本在这里是辅助准备动作，不是开始门禁。

### 4. 完成脚本作为完成门禁异步执行

点击完成时，如果 TODO 有完成脚本，后端先调度完成脚本并返回；TODO 保持进行中并显示“完成脚本执行中”。脚本成功后后端再执行现有 `CompleteTodo` 归档流程；失败时保持进行中并显示失败和重试入口。没有完成脚本时沿用现有同步完成行为。

理由：完成脚本通常承担收尾动作。如果失败后仍归档 TODO，用户很难发现和补救。备选方案是先归档再运行脚本，但失败重试位置和用户心智都会更复杂。

### 5. 后台执行器独立于嵌入式终端

新增 TODO 生命周期脚本执行器，使用 `newBackgroundCommand` 创建进程，并设置 `cmd.Dir` 为 TODO 工作目录。执行器通过 Wails 事件推送运行状态，并保存失败状态供 UI 展示和重试。

理由：后台命令在 Windows 已有隐藏控制台窗口处理，且不依赖 ConPTY 或 xterm 前端。嵌入式终端适合交互式会话，不适合生命周期任务。

### 6. 使用当前系统可用 shell 执行脚本文本

执行器根据当前 OS 和已检测/配置的 shell 运行脚本文本。Unix 使用可用 shell 执行；Windows 使用可用的 PowerShell 或 Cmd 执行。软件只保证在当前 OS 上执行用户提供的文本，不尝试把脚本转换为其他平台语法。

理由：这是跨平台应用支持，而不是跨平台脚本语言。显式保持用户脚本原样，能减少隐藏行为。

### 7. 状态模型按 TODO 和阶段记录

新增脚本执行状态按 `todoId + phase(init|complete)` 记录，状态值包含 `queued`、`running`、`failed`。成功后清除对应状态，不展示成功记录。状态事件包含脚本名称、阶段、开始时间、失败时间、退出码和截断后的错误输出。

理由：成功不需要占 UI 空间；失败需要可见且可重试。运行态是临时状态，失败态应保留到用户重试成功、删除 TODO 或完成归档清理。

## Risks / Trade-offs

- [脚本长时间运行] → 先提供运行中状态和重复触发保护，暂不提供取消和超时配置。
- [脚本输出过大] → 只保留截断后的输出尾部用于失败诊断，避免项目状态文件膨胀。
- [Windows shell 差异] → 复用现有 shell 探测和后台命令隐藏窗口逻辑，并覆盖 PowerShell/Cmd 参数构造测试。
- [应用退出时脚本仍在运行] → 初版把运行中状态视为运行时状态；应用关闭后进程由系统/上下文结束处理，重新打开时不恢复运行中任务。
- [完成脚本失败导致 TODO 不能归档] → 这是有意的门禁行为，UI 提供失败说明和重试入口。

## Migration Plan

- 现有 settings 文件缺少脚本模板字段时默认加载为空数组。
- 现有 TODO 缺少脚本快照字段时按未选择脚本处理。
- 归档和删除 TODO 时清理关联脚本执行状态。
- 回滚时删除新增字段不会影响现有 TODO 基础字段；旧版本会忽略未知 JSON 字段。

## Open Questions

- 是否需要后续增加脚本执行超时和取消能力。
- 是否需要在失败详情中提供完整日志文件入口，而不是仅展示输出尾部。
