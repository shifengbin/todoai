## Context

TODO 工作区已有 `未执行`、`执行中`、`已完成` 三个状态视图。`未执行` 和 `执行中` 列表已经在前端按用户选择的优先级或创建时间排序；`已完成` 列表当前只按状态过滤，保留输入/持久化顺序。

后端 `Todo` 模型已经包含 `completedAt`，完成 `in-progress` TODO 时会写入该字段。旧的 completed archived TODO 会在加载规范化时用 `archivedAt` 回填 `completedAt`。前端模型和已完成列表展示也已经读取 `completedAt` / `archivedAt`。

## Goals / Non-Goals

**Goals:**

- 在 `已完成` 视图中把最近完成的 TODO 排在最前面。
- 复用现有 `completedAt` 字段，并用 `archivedAt` 兼容旧数据。
- 保持 `未执行` 和 `执行中` 的现有排序控件与排序规则不变。
- 用前端组件测试覆盖已完成列表排序。

**Non-Goals:**

- 不新增后端 API、数据字段或持久化迁移。
- 不改变 TODO 完成、删除、项目快照或终端销毁流程。
- 不为 `已完成` 视图新增用户可切换的排序控件。

## Decisions

1. 在前端对已完成列表排序。

   `ProjectSidebar.vue` 已经负责把 `props.todos` 分成三个状态视图，并已包含开放 TODO 的排序 helper。把已完成排序放在同一组件内，可以保持 UI 派生状态集中在前端，避免后端 `Load` / `CompleteTodo` 返回顺序承担视图语义。

   备选方案是在 Go 层返回前排序，但这会把一个具体视图规则推到持久化管理层，并可能影响其它调用方读取 `todos` 的顺序。

2. 完成时间使用 `completedAt || archivedAt`。

   新数据应优先使用 `completedAt`。旧数据或异常数据可能只有 `archivedAt`，继续用它作为排序兜底，与现有完成时间展示逻辑一致。

   备选方案是只使用 `completedAt`，但这会让部分旧 completed archived TODO 无法按实际完成/归档时间排序。

3. 无有效完成时间的 TODO 排在最后，并在时间相同的情况下保持原始相对顺序。

   这能让缺失或无法解析时间的数据不干扰最近完成的任务，同时减少同时间戳或测试夹具数据导致的列表抖动。

## Risks / Trade-offs

- 旧数据时间字段格式异常 → 解析失败的 TODO 排到列表末尾，避免占据最新位置。
- 多个 TODO 在同一秒完成 → 依赖原始相对顺序作为稳定兜底，显示顺序可能不是严格操作顺序，但不会影响数据正确性。
- 排序逻辑位于前端 → 其它未来入口若也展示已完成 TODO，需要复用或抽取相同规则；当前只有侧栏已完成视图需要该语义。
