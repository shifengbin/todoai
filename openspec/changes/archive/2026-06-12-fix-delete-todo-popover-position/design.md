## Context

当前应用是 Wails + Go 后端 + Vue 前端。TODO 工作树由 `ProjectSidebar.vue` 渲染，删除 TODO 的入口在 TODO 右键菜单中，确认气泡使用 `.todo-action-popover` 的绝对定位样式。

当前完成 TODO 的确认气泡位于 `.todo-action-confirm-control` 内，该容器提供 `position: relative`，所以气泡能锚定在完成按钮附近。删除 TODO 的确认气泡则作为 TODO header 后的独立节点渲染，没有同等的相对定位锚点，导致绝对定位向外寻找祖先，表现为气泡跑到侧栏右上角。

## Goals / Non-Goals

**Goals:**

- 让从 TODO 右键菜单触发的删除确认气泡显示在对应 TODO 的操作上下文附近。
- 保持删除确认的现有行为：打开确认气泡时不立即删除，确认后删除，取消或外部点击后关闭。
- 复用当前侧边栏浮层互斥关闭规则，避免多个菜单/气泡同时打开。
- 增加测试约束，防止删除确认气泡再次脱离定位容器。

**Non-Goals:**

- 不改变 TODO 删除、完成、归档或终端清理的后端语义。
- 不改变项目删除、批量项目删除或 TODO 项目移除确认气泡行为。
- 不引入新的 UI 组件库或全局浮层系统。
- 不重构所有侧边栏弹出层。

## Decisions

### 1. 将删除确认气泡锚定到 TODO 操作区

删除确认气泡应渲染在与 TODO 操作按钮同级的明确定位容器内，或使用等价结构保证 `.todo-action-popover` 的绝对定位基于当前 TODO 操作区计算。这样可与完成确认气泡保持一致，避免气泡锚定到侧栏或其他上层容器。

备选方案是在 `.todo-node` 上增加 `position: relative`。这能阻止气泡锚到侧栏，但锚点会变成整条 TODO 节点，而不是具体操作区，位置仍可能与用户刚点击的菜单动作脱节。

### 2. 保持右键菜单触发流程

用户仍从 TODO 右键菜单选择删除 TODO。选择后系统关闭右键菜单并显示删除确认气泡；确认后才 emit 删除事件。这样不会改变用户已习惯的菜单入口，也不会绕过当前的删除确认。

备选方案是恢复 TODO 行外删除按钮。当前工作区已经把查看详情、添加项目和删除 TODO 收敛到右键菜单，本次修复不改变这条交互决策。

### 3. 用测试覆盖结构和行为

测试应覆盖删除菜单动作打开确认气泡后不会立即 emit，确认/取消行为仍正确，并增加定位结构或样式断言，确保删除确认气泡拥有稳定的相对定位容器。现有 jsdom 测试无法真实测量屏幕坐标，因此结构约束比截图坐标更适合单元测试。

备选方案是只做手工验证。该问题由 DOM 结构和 CSS 定位关系导致，单元测试可以低成本锁住回归点。

## Risks / Trade-offs

- [删除确认气泡移动后与完成确认气泡状态冲突] → 沿用 `todoActionConfirm` 的 `{ todoId, action }` 单一状态，确保同一时间只显示一个 TODO 操作确认气泡。
- [右键菜单点击后气泡被外部点击处理立即关闭] → 触发菜单项和气泡根节点继续阻止冒泡，并保持打开其他浮层时显式关闭当前气泡。
- [结构调整影响完成确认气泡] → 只调整删除确认气泡的锚定结构，完成确认气泡保留现有容器。
- [测试无法验证真实坐标] → 通过 DOM 归属和 CSS 定位容器断言覆盖根因，再用人工运行界面确认视觉位置。

## Migration Plan

1. 调整 `ProjectSidebar.vue` 中删除 TODO 确认气泡的渲染位置，使其拥有与当前 TODO 操作区对应的相对定位锚点。
2. 必要时补充或收敛 `style.css` 中 `.todo-action-popover` 和定位容器样式。
3. 更新 `ProjectSidebar` 测试，覆盖删除确认气泡的打开、取消、确认、互斥关闭和定位容器。
4. 运行前端单元测试与构建。

回滚时只需恢复前端模板、样式和测试；后端 API、持久化结构和用户数据不受影响。
