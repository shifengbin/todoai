## Context

当前生命周期脚本能力已经覆盖全局脚本模板、创建 TODO 时选择脚本快照、TODO 开始/完成时异步执行脚本，以及运行中/失败状态展示。现有模型只保存固定脚本文本，无法让同一个模板在不同 TODO 上填写不同参数。

本变更需要同时影响 Go 持久化模型、脚本执行器、Wails 前后端类型和 Vue 表单。参数值要求明文保存，不需要 secret 保护；主要复杂点是避免让用户在脚本中分别学习 bash/zsh/fish、PowerShell、cmd 的变量语法。

## Goals / Non-Goals

**Goals:**

- 支持脚本模板定义明文字符串参数。
- 支持创建 TODO 时为选中的脚本模板填写参数值。
- 将参数定义和值保存到 TODO 脚本快照中，保证重试和历史 TODO 不受全局模板修改影响。
- 支持脚本中使用统一占位符 `{{param_name}}`，执行前渲染为当前 shell 可执行的字符串字面量。
- 保持现有未使用参数的生命周期脚本行为不变。

**Non-Goals:**

- 不支持 secret 参数、加密存储或日志脱敏。
- 不支持参数类型系统；第一版仅支持字符串。
- 不提供脚本语言跨平台翻译；只处理参数值字面量转义。
- 不要求所有参数必须在脚本中被引用，也不强制解析完整脚本语法。

## Decisions

### 1. 参数定义随模板保存，随 TODO 快照复制

新增脚本参数定义结构，建议字段为 `name`、`label`、`description`、`defaultValue`、`required`。`TodoLifecycleScriptTemplate` 保存参数定义；`TodoLifecycleScriptSnapshot` 保存脚本文本、参数定义和 `parameterValues`。

理由：这延续现有“创建 TODO 时保存脚本快照”的设计。脚本模板后续被修改时，已创建 TODO 的脚本、参数定义和值都保持创建时语义。备选方案是 TODO 只保存模板 ID 和参数值，但会让历史 TODO 重试时依赖当前全局模板，行为不可预测。

### 2. 参数名是稳定标识，显示名称只用于 UI

参数名用于占位符和参数值映射，校验为 `[A-Za-z_][A-Za-z0-9_]*`，同一脚本模板内不得重复。显示名称可为空；为空时 UI 使用参数名展示。必填参数在创建 TODO 时必须填写非空值；非必填参数未填写时保存为空字符串并渲染为空字符串字面量。

理由：参数名需要可预测、跨平台、可作为 map key。保留独立显示名称可以让 UI 使用中文描述，而脚本继续使用稳定英文标识。

### 3. 使用占位符渲染作为推荐脚本接口

脚本文本使用 `{{param_name}}` 引用参数。执行前，系统只替换已声明参数对应的占位符，并根据当前 shell 生成安全字符串字面量。未声明的 `{{...}}` 文本保持原样，以避免破坏已有脚本中的花括号语法。

理由：环境变量只污染当前进程，不会污染全局环境，但脚本读取方式仍有 `$VAR`、`$env:VAR`、`%VAR%` 差异。占位符让脚本模板用统一写法表达参数位置。备选方案是只注入环境变量，但它无法隔离不同 shell 的语法差异。

### 4. shell 转义集中在后端执行器

在 `todo_lifecycle_script.go` 附近增加参数渲染函数，执行器在构造 `exec.Cmd` 前渲染脚本文本。渲染函数按 shell 类型选择字符串字面量策略：

- bash/zsh/fish/sh：单引号字面量，内部单引号按 Unix shell 规则转义。
- PowerShell/pwsh：单引号字面量，内部单引号用 `''` 转义。
- cmd：双引号字面量，并按 cmd 规则处理引号和特殊字符。
- 未识别 shell：使用当前非 Windows 的 POSIX 策略或 Windows 的 cmd 策略作为保守默认。

理由：脚本执行已经在后端根据 shell 构造命令参数，把渲染放在同一层可以集中测试，并避免前端承担 shell 细节。

### 5. 前端在脚本选择后动态展示参数输入

脚本管理表单以单行摘要展示已有脚本模板，摘要包含名称、描述、初始化脚本摘要、完成脚本摘要和参数数量；点击展开后进入多行编辑态，展示完整名称/描述输入、初始化/完成脚本 textarea 和参数区域。新增脚本默认展开，便于立即编辑。参数区域在脚本展开态内独立折叠，默认仅展示参数数量、问号帮助和添加按钮；用户展开参数区域或点击添加参数后，再展示参数明细表单。

参数标题旁提供问号帮助提示。创建 TODO 表单选择脚本后，根据所选脚本的参数定义展示输入框，并用默认值初始化；参数输入区域同样提供问号帮助提示。提示内容说明统一占位符写法 `{{参数名}}`、示例 `git checkout -b {{branch_name}}`，以及不要额外加引号、系统会按当前 shell 自动转义、未定义占位符保持原样、参数明文保存等注意事项。帮助提示使用固定定位浮层渲染，避免被脚本管理弹窗或滚动区域裁剪。切换脚本时重建参数值，避免把旧脚本参数混入新脚本快照。

理由：参数值属于本次 TODO 创建输入，必须在提交前明确展示。切换脚本时重建值可以降低保存无效参数的概率。

## Risks / Trade-offs

- [cmd 转义规则复杂] → 将 cmd 字面量转义独立成函数并覆盖包含空格、引号、百分号和命令分隔符的单元测试。
- [未知占位符保持原样可能隐藏拼写错误] → 第一版优先保护向后兼容；后续可在 UI 增加“未声明占位符”提示。
- [明文参数可能包含敏感信息] → 本变更明确不支持 secret，UI 和文档按明文参数处理。
- [参数定义和值快照增加状态文件体积] → 参数为短字符串列表，影响可控；无需引入外部存储。

## Migration Plan

- 现有脚本模板缺少参数字段时按空参数列表加载。
- 现有 TODO 脚本快照缺少参数定义和值时按空参数列表执行，脚本文本保持原样。
- 回滚到旧版本时，旧版本会忽略未知 JSON 字段；已保存的基础脚本字段仍可使用。
