## Context

当前应用中，TODO、项目和选中上下文由 `ProjectManager` 持久化到 `projects.json`，但 `ProjectState.Terminals` 由 `App.withShellState()` 从 `ShellSessionManager` 的运行时状态覆盖。应用关闭后，shell 进程和终端描述都会消失，前端 xterm scrollback 也随页面生命周期丢失。

用户这次需要的是应用关闭后重新打开时恢复“之前打开过哪些终端”和“终端历史输出”，用于回忆上次上下文；不需要恢复 PTY 进程，也不需要继续执行关闭前的命令。TODO 行菜单方面，现有右键菜单已经承载查看详情、添加项目、复制描述、删除 TODO，但缺少可见入口，复制内容也缺少标题。

## Goals / Non-Goals

**Goals:**

- 在应用重开后恢复活动 TODO 项目下的终端记录和最近输出历史。
- 恢复后的终端显示为非运行状态，不自动启动 shell 进程。
- 保存输出历史时设置容量上限，避免本地配置数据无限增长。
- 终端、TODO、TODO 项目、项目被移除时清理对应历史。
- 在 TODO 行增加三点菜单按钮，复用右键菜单功能。
- 将 TODO 复制动作改为复制标题和描述，剪贴板第一行是标题，第二行开始是描述。

**Non-Goals:**

- 不恢复关闭应用前的 shell 进程、PTY 状态、运行中命令或工作目录内进程。
- 不实现完整命令历史数据库、搜索、导出或跨设备同步。
- 不把已完成 TODO 的终端恢复为可操作终端。
- 不改变 TODO 的工作流状态规则、项目关联规则或终端启动配置语义。

## Decisions

### 持久化终端快照，而不是运行时 session

引入持久化终端快照，保存 terminal id、TODO id、TODO project id、project id、shell 名称、创建时间、上次选中时间、状态和最近输出。应用启动时把有效快照恢复为终端列表，状态规范化为 `exited`，并回放输出到对应 xterm。

原因：用户需要的是回忆上下文，不是恢复进程。把恢复状态标记为非运行可以避免误导用户以为命令仍在执行。

替代方案：持久化运行时 terminal 到现有 `projects.json`。这会让项目配置文件快速变大，也把高频输出写入和低频项目配置混在一起，回滚和清理都更难。

### 输出历史使用独立存储并限制容量

优先使用项目配置旁的独立文件保存终端历史，例如 `terminal-history.json`。每个 terminal 只保留最近一段输出，建议用字节上限实现第一版，例如每个 terminal 最近 200KB。实现时可以按字节裁剪并保证字符串有效；如果同时实现行数上限，也应以字节上限作为硬限制。

原因：终端输出可能非常大，独立存储和硬上限能保护应用启动性能和配置目录大小。

替代方案：完全依赖 xterm scrollback。xterm scrollback 只在当前前端生命周期内存在，无法满足应用重开恢复。

### 后端负责持久化，前端负责回放

后端在创建、选择、删除 terminal 和接收 PTY 输出时更新快照；`ListProjects` 等返回状态时包含已恢复的 terminal 描述和历史输出。前端在创建/激活 xterm session 后，将历史输出写入对应 terminal，再继续接收实时 `terminal-output` 事件。

原因：后端能统一处理应用关闭、TODO/项目清理和数据迁移；前端仍专注渲染和交互。

### 清理语义跟随现有终端生命周期

删除 terminal 时清理该 terminal 历史。完成或删除 TODO、移除 TODO 项目、删除项目时，清理其拥有的 terminal 快照和历史输出。若应用启动时发现快照引用的 TODO、TODO project 或项目已不存在，也应丢弃这些快照。

原因：历史终端不应绕过现有 TODO 工作区可见性和删除语义。

### TODO 菜单只新增入口，不复制菜单逻辑

TODO 行增加一个三点图标按钮，点击时打开与右键相同的菜单状态和菜单项。右键和三点按钮共享关闭规则、确认气泡互斥规则和事件 emit。

原因：避免两套路由导致行为漂移，也便于现有测试扩展。

## Risks / Trade-offs

- [Risk] 频繁写入终端输出会增加磁盘 IO。→ Mitigation: 在输出事件路径中进行内存聚合并节流保存，或只在输出到达后 debounce 写入。
- [Risk] 输出内容可能包含敏感信息。→ Mitigation: 只保存最近有限输出，并随删除 terminal/TODO/project 清理；后续如需要可增加设置开关。
- [Risk] 历史输出回放和实时输出可能重复。→ Mitigation: 恢复时只回放持久化历史一次，实时事件只追加应用启动后的新输出。
- [Risk] 旧数据没有终端历史文件。→ Mitigation: 缺失历史文件视为空历史，保持现有项目/TODO 加载行为。
- [Risk] 恢复终端列表可能让用户误以为 shell 仍在运行。→ Mitigation: 恢复终端状态统一为 `exited`，终端区域继续显示退出/历史状态提示，不自动启动 shell。
