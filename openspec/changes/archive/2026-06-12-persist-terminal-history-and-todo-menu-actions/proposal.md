## Why

用户关闭应用后重新打开时，之前打开过的终端和历史输出都会丢失，导致很难回忆上次在某个 TODO 项目终端里做了什么。TODO 行上的管理操作目前主要依赖右键菜单，不够可发现，同时“复制描述”不能把 TODO 标题一起带上，粘贴到外部工具时上下文不足。

## What Changes

- 应用重开后恢复之前打开过的 TODO 项目终端记录，包括终端所属 TODO、项目、shell 名称、创建时间、上次选中时间和上次选中的终端。
- 为每个已恢复的终端回放最近的历史输出，方便用户查看上次上下文；不恢复 shell 进程，也不继续执行关闭应用前正在运行的命令。
- 终端输出历史保存需要有容量上限，避免长日志无限撑大本地配置数据。
- 删除终端、完成或删除 TODO、移除 TODO 项目、删除项目时，同步清理不再可见的终端历史。
- 在 TODO item 上增加三点图标按钮，点击后打开与右键 TODO 菜单一致的下拉菜单。
- 将“复制描述”改为“复制标题和描述”，剪贴板内容第一行为 TODO 标题，第二行开始为 TODO 描述内容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `embedded-shell-sessions`: 终端记录和最近输出历史需要在应用关闭后重新打开时恢复，但 shell 进程和命令执行状态不恢复。
- `todo-workspace`: TODO 行需要提供可见的三点菜单入口，并调整复制 TODO 文本的剪贴板格式。

## Impact

- 后端：终端记录和输出历史需要新增持久化读写路径，并与现有 shell session 生命周期、TODO/项目删除清理逻辑保持一致。
- 前端：`App.vue` 和 `terminalManager.js` 需要支持接收已恢复终端历史并回放到 xterm；`ProjectSidebar.vue` 需要增加 TODO 三点菜单入口和复制菜单文案调整。
- Wails 模型：`ProjectTerminal` 或相关返回状态可能需要携带历史输出，生成的前端模型需要同步更新。
- 测试：需要覆盖应用重开后的终端列表恢复、历史输出回放、历史清理、三点菜单交互和复制标题/描述格式。
