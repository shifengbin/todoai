## Context

当前应用是 Wails + Go 后端 + Vue 前端。现有工作区状态以 `ProjectState` 为核心，持久化项目列表和活动项目，终端由 `ShellSessionManager` 在运行时按 `projectId` 管理。前端侧边栏当前是单一 `Projects` 树，项目行下面直接显示终端行；选择项目会自动确保默认终端存在。

新的目标是让 TODO 成为主要工作上下文。用户通过任务切换来记住终端用途，同一个项目可以参与多个 TODO，但每个 TODO 下的终端必须完全隔离。项目视图保留为项目库管理入口，不再作为终端入口。

## Goals / Non-Goals

**Goals:**

- 引入 TODO、TODO 项目关联和归档历史，并持久化这些数据。
- 将侧边栏拆成 TODO tab 和项目 tab。
- 在 TODO tab 中展示 `TODO -> 项目 -> 终端`，并从该上下文创建、选择和删除终端。
- 允许同一个项目关联多个 TODO，并按 TODO 项目上下文隔离终端。
- 支持选择父目录并批量导入第一层子目录为项目。
- 完成或删除 TODO 时关闭并销毁该 TODO 下所有运行时终端，并保留可查看的归档记录。
- 删除项目时从所有 TODO 关联中移除该项目，并关闭该项目在所有 TODO 下的运行时终端。

**Non-Goals:**

- 第一版不支持从归档恢复 TODO。
- 第一版不支持原生多目录选择器；批量导入只通过选择父目录实现。
- 第一版不持久化终端会话本身；终端仍只在当前应用运行期间存在。
- 第一版不在项目 tab 中提供终端创建、选择或只读终端总览。

## Decisions

### 1. 使用统一工作区状态承载项目和 TODO

后端保留 JSON 配置文件持久化方式，将现有 `ProjectState` 演进为工作区状态，新增：

- `todos[]`
- `todoProjects[]`
- `activeTodoId`
- `activeTodoProjectId`
- `activeProjectId`
- `activeTerminalId`

`Project` 继续表示全局项目库。`Todo` 表示任务，包含标题、状态、归档原因和时间。`TodoProject` 表示 TODO 与项目之间的多对多关联，并记录该关联自己的选择时间。终端运行态返回给前端时包含 `todoId`、`todoProjectId` 和 `projectId`。

替代方案是为 TODO 单独建立配置文件或 SQLite。当前数据量小、已有 JSON 持久化和测试模式清晰，继续扩展 JSON 风险更低。

### 2. 终端归属到 TODO 项目上下文

`ShellSessionManager` 的活动索引从 `activeByProject[projectId]` 调整为按 TODO 项目上下文索引，例如 `activeByTodoProject[todoProjectId]`。创建终端时需要传入 TODO 项目关联和项目路径；同一个 `projectId` 在不同 TODO 下会创建不同终端集合。

这比只给 `ProjectTerminal` 加 `todoId` 但继续按 `projectId` 查找更严格，可以避免选择或复用终端时跨 TODO 串线。

### 3. 项目 tab 是管理视图，TODO tab 是终端入口

项目 tab 只展示项目库、单项目导入、父目录批量导入、删除项目和不可用状态。用户不能从项目 tab 创建或选择终端。需要操作终端时，用户必须进入 TODO tab，并在某个 TODO 下选择或添加项目。

替代方案是在项目 tab 中按 TODO 分组展示终端，但这会让用户继续按项目理解终端，削弱 TODO 主线。

### 4. 归档保存项目快照，不保存终端

完成或删除 TODO 时，系统关闭并删除该 TODO 下运行时终端，然后将 TODO 标记为归档状态，并保存当时关联项目的名称、路径和项目 ID 快照。归档视图只展示历史上下文，不恢复终端进程。

保存快照可以避免后续删除项目后归档记录失去可读信息。

### 5. 父目录批量导入只扫描第一层子目录

批量导入使用现有 Wails v2 的目录选择能力选择一个父目录，然后后端枚举第一层可访问子目录。每个子目录按现有项目创建规则加入项目库，重复绝对路径跳过。导入完成后返回添加数量、跳过数量和最新工作区状态。

不递归扫描可以避免误导入大量嵌套依赖目录，并保持操作结果可预测。

### 6. 旧配置迁移为无 TODO 的项目库

加载旧配置时，已有 `projects` 继续保留在项目库中，`todos` 和 `todoProjects` 初始化为空，旧运行时终端不需要迁移。由于终端不持久化，迁移只涉及 JSON schema 默认值。

## Risks / Trade-offs

- [状态模型扩大] → 为工作区状态管理器增加聚焦测试，覆盖旧配置加载、TODO 关联、项目删除和归档。
- [终端索引迁移容易遗漏 projectId 假设] → 在 `ShellSessionManager` 测试中覆盖同一项目在两个 TODO 下创建终端且互不影响。
- [完成 TODO 时关闭终端可能中断长任务] → 完成和删除 TODO 前由前端确认，后端仍保证清理是原子生命周期行为。
- [项目删除影响多个 TODO] → 删除项目时返回更新后的工作区状态，并从归档外的 TODO 关联中移除项目；归档快照不受影响。
- [父目录批量导入结果不明显] → API 返回导入摘要，前端在状态栏显示添加和跳过数量。
- [Git 状态依赖活动项目] → 活动项目应来自当前 TODO 项目上下文；没有活动 TODO 项目时显示空状态，不从项目 tab 隐式切换终端上下文。

## Migration Plan

1. 扩展后端状态结构和加载默认值，确保旧 `projects.json` 可继续读取。
2. 增加 TODO 和 TODO 项目关联 API，再调整终端 API 使用 TODO 项目上下文。
3. 更新前端 bindings。
4. 将前端侧边栏拆成 tab，并先接入项目 tab 的现有项目库操作。
5. 接入 TODO tab、归档视图和 TODO 级终端树。
6. 运行 Go 测试、前端单元测试和前端 build。

回滚策略是保留旧配置字段兼容读取。若新 UI 或 TODO 状态出现问题，可以回退到旧代码；旧代码会忽略未知 JSON 字段，但不会理解新 TODO 数据。

## Open Questions

- 归档记录是否需要长期删除功能；第一版不实现。
- TODO 标题是否需要重命名；第一版可只支持创建时命名，后续按需要补充编辑。
