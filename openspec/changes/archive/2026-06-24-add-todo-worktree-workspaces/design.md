## Context

应用当前以 workspace 为顶层数据边界，TODO 可以关联多个全局项目候选的副本，终端按 `TODO -> 项目 -> 终端` 隔离运行时状态。现有项目副本保存项目名称、路径和来源候选 ID，但同一项目路径在不同 TODO 中仍指向同一个文件系统目录，实际代码改动和 Git 分支没有隔离。

已有 workspace 全局终端以 workspace 根目录作为工作目录，已有 TODO 项目终端以项目路径作为工作目录。本变更引入任务工作区目录作为新的任务级文件系统上下文，并让 TODO 项目终端进入任务目录下的 Git worktree。

## Goals / Non-Goals

**Goals:**

- 为每个进入执行态的任务准备独立任务工作区目录。
- 为任务中每个 Git 项目创建任务内 worktree，使不同任务的项目改动互不冲突。
- 支持任务级终端，工作目录为任务工作区目录。
- 支持项目级终端，工作目录为任务目录下对应项目 worktree。
- 在项目选择时记录 base 分支或用户输入的新分支名。
- 自动维护任务目录中的 `README.md`，用于后续合并提示。
- 保留任务目录和 worktree，交由用户手动清理。

**Non-Goals:**

- 不自动合并、推送或删除分支。
- 不在任务完成时自动删除 worktree 或任务目录。
- 不为非 Git 项目创建 worktree；非 Git 项目的处理仅限阻止 worktree 准备并展示错误状态。
- 不重命名已经创建的任务目录，即使任务标题或描述被编辑。

## Decisions

### 任务工作区目录

任务工作区根目录使用 workspace 根目录下的固定目录，例如 `tasks/`。每个任务第一次准备工作区时，根据当时的 `title + description` 计算 MD5 作为目录名，并把目录名或绝对路径持久化到 TODO 数据中。后续编辑任务标题或描述只更新 `README.md`，不重命名目录。

选择 MD5 而不是可读 slug 的原因是避免中文、特殊字符、超长标题和重名任务导致路径不稳定。目录名持久化后可以避免编辑任务时影响终端历史和 Git worktree 元数据。

### README 生成

任务工作区创建后写入 `README.md`。每次任务标题、任务描述、项目关联、base 分支或 worktree 分支变化后，后端重新生成整个 README 文件，而不是局部修改。格式为：

```md
# 任务: [任务名称]

## 任务详情

[任务描述]

## 项目信息

1. [项目名称]: base分支为[分支名称], 当前worktree分支为[worktree分支名称];
```

任务描述为空时，`## 任务详情` 下保持空白。重新生成整个文件可以避免删除项目、重排项目或修改分支后残留旧内容。

### 分支选择和 worktree 分支

项目选择控件为每个选中项目提供分支下拉和输入。未选择时默认主分支，主分支优先从仓库默认分支识别，无法识别时使用 `main`，再失败时使用 `master`。

创建 worktree 时分两种情况：

- 用户选择或输入的是已存在分支：该分支作为 base 分支，系统创建任务隔离 worktree 分支，并从 base 分支创建 worktree。
- 用户输入的是不存在分支：系统从主分支创建这个用户输入的分支，并让 worktree checkout 到该新分支。

分支冲突处理：

- 如果目标 worktree 路径已存在且不是当前任务记录的 worktree，系统阻止创建并提示。
- 如果目标分支已经被其他 worktree checkout，系统阻止创建并提示用户更换分支名。
- 如果 Git 不可用、项目不是 Git 仓库或 base 分支不存在，系统记录项目 worktree 准备失败，项目终端不可创建。

### 数据模型

TODO 增加任务工作区目录字段，例如 `workspaceDirName` 或 `workspacePath`。TODO 项目副本增加：

- `baseBranch`
- `worktreeBranch`
- `worktreePath`
- `worktreeStatus`
- `worktreeError`

这些字段属于 workspace `.data/projects.json` 的持久化数据。目录和 worktree 本身保存在 workspace 根目录下的任务工作区根目录中，不放入 `.data`。

旧数据中缺少这些字段时，按未准备任务工作区和未准备 worktree 处理，不影响现有 TODO 展示。

### 任务准备时机

任务从 `not-started` 变为 `in-progress` 时准备任务工作区，并为已关联项目创建 worktree。执行中任务新增项目时立即为新增项目创建 worktree。创建 TODO 时如果仍为 `not-started`，只保存分支选择，不创建目录或 worktree。

这个时机避免大量未开始任务提前占用磁盘和 Git worktree，同时保证真正执行的任务默认获得隔离。

### 终端归属和工作目录

新增任务级终端，归属于 TODO，不归属于 TODO 项目。任务级终端创建条件与任务执行态绑定，工作目录为任务工作区目录。TODO 项目终端继续归属于 TODO 项目，但工作目录从原项目路径改为该 TODO 项目记录的 `worktreePath`。

终端历史需要能区分 workspace 全局终端、任务终端和 TODO 项目终端。选择任务终端不改变当前 TODO 项目 Git 状态上下文；选择 TODO 项目终端仍更新 TODO 项目上下文。

### 打开文件夹

后端提供打开任务文件夹和打开项目 worktree 文件夹的 API。TODO 行菜单显示“打开任务文件夹”，TODO 项目行菜单显示“打开项目文件夹”。如果目录尚未创建或不可访问，系统显示非阻断错误。

### 手动清理

任务完成后不自动清理目录或 worktree。后续可独立增加清理入口；本变更只要求目录保留，并提供打开目录能力。

## Risks / Trade-offs

- Git worktree 创建失败导致任务进入执行态但部分项目不可用 -> 持久化每个项目的准备状态和错误，允许用户修复分支/仓库后重试。
- 用户输入不存在分支名可能与远端分支预期不一致 -> UI 文案区分“已存在分支”和“将从主分支创建新分支”。
- 任务目录使用 MD5 不可读 -> README 和菜单打开能力补足可理解性；路径稳定性优先于可读性。
- README 自动重写可能覆盖用户手动编辑 README -> 将 README 作为系统生成文件处理；后续如果需要用户笔记，可另建用户笔记文件。
- worktree 目录保留会占用磁盘 -> 符合用户手动清理要求，后续可添加清理辅助但不自动删除。
- 主分支识别在无远端或非常规仓库中可能失败 -> 按默认分支、`main`、`master` 的顺序尝试，并在失败时提示用户选择存在分支。

## Migration Plan

旧 workspace 打开时不创建任务目录，也不自动创建 worktree。只有任务进入执行态、执行中任务新增项目或用户触发准备/重试时，才补齐任务工作区和 worktree 字段。

回滚时，已有任务目录和 Git worktree 保留在磁盘上，不删除用户文件。应用只会忽略新增持久化字段；若需要人工清理，用户可通过文件系统或 Git 命令处理。

## Open Questions

- 任务工作区根目录最终命名使用 `tasks/` 还是可配置名称；当前设计默认使用 `tasks/`。
- 非 Git 项目未来是否允许复制目录作为任务隔离副本；当前设计不支持。
