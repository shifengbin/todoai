## Context

当前应用是 Wails + Go 后端 + Vue 前端。项目库由 `ProjectSidebar.vue` 的 `项目` tab 渲染，`App.vue` 调用 Wails 绑定的 `DeleteProject` 完成删除。单个项目删除现在通过 `window.confirm` 确认；TODO 完成/删除和 TODO 下项目移除已经使用按钮旁的气泡确认。

项目删除的后端语义已经存在：只删除应用内项目记录，移除活动 TODO 关联，关闭该项目所有运行时终端，不删除磁盘文件，并保留 archived TODO 快照。这次变更应保持这些语义，只调整项目库交互并增加批量删除入口。

## Goals / Non-Goals

**Goals:**

- 项目库单项删除使用项目行内的气泡确认，和 TODO 区域确认体验保持一致。
- 项目库支持勾选多个项目，并通过顶部“删除选中”操作批量删除。
- 批量删除使用后端一次性 API 返回完整 `ProjectState`，避免前端逐个删除带来的部分成功状态。
- 批量删除沿用单项删除语义：不删除磁盘文件，清理活动关联和对应终端。

**Non-Goals:**

- 不增加恢复/回收站能力。
- 不删除项目目录或项目内文件。
- 不改变 TODO tab 下项目关联移除的既有语义。
- 不增加复杂的跨页选择、筛选或全局选择模式；当前项目库列表内勾选即可。

## Decisions

### 单项删除确认下沉到 ProjectSidebar

项目库行的删除按钮点击后只打开本行确认气泡，确认后再 emit `delete-project`。`App.vue` 的 `deleteProject` 不再调用 `window.confirm`。

替代方案是在 `App.vue` 保留确认逻辑，但这样确认 UI 仍脱离按钮上下文，且无法和侧栏已有气泡状态互斥复用。

### 批量选择状态由侧栏维护

`ProjectSidebar.vue` 维护 `selectedProjectIds`，项目行左侧显示复选框。复选框点击不触发项目行选择。项目列表变化时清理不存在的选中 ID；切换 tab 或打开其他浮层时关闭项目删除确认气泡。

替代方案是把选中状态提升到 `App.vue`。当前选中态只是项目库视图的临时 UI 状态，提升后会扩大父组件状态面，收益不高。

### 批量删除使用新增后端 API

新增 `DeleteProjects(projectIDs []string)`，由 `App` 暴露给前端。`ProjectManager` 在同一次锁和保存流程中验证项目 ID、删除项目、删除活动 TODO 关联并更新 active project。`App.DeleteProjects` 在项目状态保存成功后，对每个删除项目调用 shell manager 的项目终端清理，再返回 `withShellState(state)`。

替代方案是前端循环调用 `DeleteProject`。这会带来部分删除成功、后续失败、active 状态多次跳转和终端多次激活同步的问题，用户也更难理解错误后的状态。

### 批量 API 采用全有或全无的输入校验

批量删除会去重并忽略空 ID；如果去重后为空，或任一 ID 不在项目库中，则返回错误且不修改持久化状态。校验通过后才保存删除结果。这样测试和 UI 错误处理都更直接。

替代方案是跳过不存在的 ID 并删除其余项目。该策略更宽松，但会掩盖前端状态过期或调用错误。

## Risks / Trade-offs

- [新增复选框挤占项目名宽度] -> 使用固定宽度选择列，并保留项目名/路径省略规则。
- [批量删除 active project 后选中状态混乱] -> 复用现有 most-recent active project 选择逻辑；删除结果返回后清理前端选中集合。
- [删除多个项目会关闭多个运行终端] -> 确认气泡文案显示删除数量，并在规范中明确会关闭这些项目关联的运行时终端。
- [Wails 绑定未同步导致前端调用失败] -> 任务中包含绑定生成/同步步骤和类型声明检查。
