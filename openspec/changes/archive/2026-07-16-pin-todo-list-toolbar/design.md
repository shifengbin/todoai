## Context

`ProjectSidebar.vue` 当前将工作流状态页签放在 `.todo-workspace-scroll` 之外，因此页签不会随列表滚动；共享的 `.todo-tree-toolbar` 仍是该滚动容器的第一个子元素。工具栏在 `未执行` 和 `执行中` 视图显示排序与全部展开/收起控件，在 `已完成` 视图显示已选数量与批量删除控件，所以三个视图的高频操作都会在长列表向下滚动后离开可视区域。

`.todo-workspace-scroll` 同时是普通列表滚动区域、弹窗打开时的滚动锁定目标，以及手动排序时传给 SortableJS 的边缘自动滚动目标。本变更必须固定整个共享工具栏，同时保留这些滚动职责和现有业务交互。

## Goals / Non-Goals

**Goals:**

- 让三个 TODO 状态视图共用的工具栏在列表滚动期间始终可见。
- 只让当前 TODO 列表占用剩余高度并独立滚动。
- 保持排序、批量展开/收起、已完成 TODO 选择与批量删除行为不变。
- 保持手动排序的鼠标、触控和键盘交互，以及拖拽边缘自动滚动能力不变。
- 通过 DOM 层级、CSS 布局合同和现有交互测试防止布局回归。

**Non-Goals:**

- 不改变 TODO 排序规则、展开状态模型或已完成 TODO 批量删除规则。
- 不修改后端 API、Wails 绑定、工作区 UI 状态或其他持久化数据。
- 不调整工作流状态页签、侧栏标题栏或终端区域的固定方式。
- 不引入新的滚动库、拖拽库或响应式断点。

## Decisions

### 1. 将共享工具栏移出列表滚动容器

在 `.project-list` 的纵向 flex 布局中，保持工作流状态页签在最上方，将 `.todo-tree-toolbar` 放在页签之后、`.todo-workspace-scroll` 之前。滚动容器只包裹当前视图的 TODO 列表：

```text
.project-list
├── .todo-view-tabs
├── .todo-tree-toolbar
└── .todo-workspace-scroll
    └── 当前视图的 TODO 列表
```

该结构延续项目固定工作流状态页签时采用的 DOM 拆分方式，使固定行为由滚动边界直接保证。备选方案是为工具栏设置 `position: sticky`，但它需要额外处理背景覆盖、层级、滚动容器内边距和确认浮层，且仍让工具栏在语义上属于滚动内容，因此不采用。

### 2. 保留一套按视图切换内容的共享工具栏

工具栏继续使用现有 `isOpenTodoView` 分支：开放视图渲染排序与全部展开/收起控件，已完成视图渲染选择数量与批量删除控件。移动整个工具栏而不是只移动开放视图控件，可保证三个视图行为一致，并避免复制状态、事件处理器或无障碍属性。

### 3. 保持现有滚动元素和拖拽滚动目标

`todoWorkspaceScrollElement` 的 `ref`、`overflow-y: auto`、隐藏滚动条规则以及弹窗打开时的滚动锁定规则继续绑定 `.todo-workspace-scroll`。SortableJS 的 `scroll` 选项仍指向该元素；由于工具栏不再占用滚动内容高度，边缘自动滚动只作用于实际 TODO 列表，现有拖拽数据流无需修改。

### 4. 用 flex 尺寸和一致间距维持稳定布局

状态页签与共享工具栏作为不可收缩的固定行，滚动容器继续使用 `flex: 1 1 auto`、`min-height: 0` 消耗剩余高度。工具栏与滚动列表保留一致的右侧留白，避免移出带右侧内边距的滚动容器后控件与列表边缘错位。空列表仍保留滚动区域的剩余高度，不改变侧栏或终端区域尺寸。

### 5. 测试布局合同而不模拟浏览器滚动引擎

组件测试验证工作流状态页签和共享工具栏均不属于 `.todo-workspace-scroll`，且三种视图继续显示各自正确的控件。样式合同测试验证工具栏不可收缩、滚动容器仍可滚动并隐藏滚动条。现有 SortableJS 配置测试继续断言滚动目标为 `.todo-workspace-scroll`，从而覆盖拖拽自动滚动的集成边界。

## Risks / Trade-offs

- **风险：工具栏移出滚动容器后与列表右边缘不对齐。** → 为固定工具栏保留与滚动内容一致的右侧留白，并通过样式合同测试锁定布局。
- **风险：新增固定行挤压小高度窗口中的列表空间。** → 工具栏保持当前紧凑高度且不可收缩，列表通过 `min-height: 0` 使用剩余空间并继续滚动。
- **风险：滚动元素层级变化破坏拖拽边缘自动滚动。** → 保留原 `ref` 和 SortableJS `scroll` 目标，并继续运行现有拖拽配置测试。
- **风险：已完成视图的批量删除确认浮层发生裁剪或定位变化。** → 保持工具栏内部 DOM 与定位上下文不变，并在组件测试中覆盖切换、打开和确认流程。

## Migration Plan

本变更只调整前端 DOM 层级、CSS 和测试，无数据迁移或分阶段发布要求。若出现布局回归，可恢复工具栏原有嵌套层级及对应样式，不影响任何持久化状态。

## Open Questions

无。固定范围已确认覆盖 `未执行`、`执行中` 和 `已完成` 三个视图的共享工具栏。
