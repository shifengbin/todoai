## Context

当前 TODO 工作区由后端返回 `state.todos`，前端侧边栏在 `ProjectSidebar.vue` 中通过 `activeTodos` 和 `archivedTodos` 派生列表。活动 TODO 目前只按 `status === 'active'` 过滤后直接渲染，因此展示顺序等同于后端持久化数组顺序。

TODO 模型已经包含 `priority` 和 `createdAt` 字段，且旧数据缺少优先级时已有按 `中` 处理的要求。本变更只改变活动 TODO 列表的展示顺序，不需要扩展数据模型。

## Goals / Non-Goals

**Goals:**

- 活动 TODO 列表提供可见排序切换控件。
- 默认按 `高`、`中`、`低` 优先级展示，相同优先级内按 `createdAt` 创建时间正序展示。
- 用户可切换为按 `createdAt` 创建时间正序展示。
- 归档 TODO 列表保持现状，不应用活动列表排序。
- 保持现有后端 API、持久化格式和 TODO 选择行为不变。

**Non-Goals:**

- 不持久化排序偏好。
- 不增加 `updatedAt` 或按最近修改时间排序。
- 不改变归档 TODO 列表的排序规则。

## Decisions

### 在前端派生列表中排序并维护本地排序状态

活动 TODO 排序应在 `ProjectSidebar.vue` 的 `activeTodos` computed 中完成，并由组件本地状态记录当前排序模式。这样排序只影响展示层，不会改变 `state.todos` 的持久化顺序，也不会影响后端状态保存、归档、删除或选择逻辑。

替代方案是后端在返回 `ProjectState` 时排序 `Todos`。该方案会让所有消费者都看到重排后的数组，并可能把展示规则混入状态管理；当前需求只约束活动列表展示，因此前端派生排序更小、更直接。

### 使用分段控件切换排序模式

活动 TODO 工具栏应提供两个可见按钮：优先级和时间。优先级按钮为默认选中状态；点击时间按钮后，活动列表改为仅按 `createdAt` 正序展示。排序模式不持久化，刷新或重新挂载组件后恢复默认优先级排序。

替代方案是下拉菜单。当前只有两个互斥选项，分段按钮更直接，也与现有工具栏按钮的交互复杂度相匹配。

### 使用稳定的显式优先级权重

排序逻辑应使用显式映射：`high = 0`、`medium = 1`、`low = 2`。缺失或未知优先级按 `medium` 处理，以匹配既有旧数据兼容要求。

替代方案是按优先级文案或字符串字典序排序。该方案依赖展示值或字符串顺序，不如显式权重清晰。

### 同优先级按创建时间正序

同优先级 TODO 使用 `createdAt` 正序排序，先创建的在上。时间值应按可比较的时间语义处理；若遇到缺失或无法解析的时间，保留可预测的兜底顺序，避免界面抖动。

## Risks / Trade-offs

- 前端排序后，列表视觉顺序与持久化数组顺序不同 -> 将排序限制在 `activeTodos` computed，并通过组件测试固定预期。
- 排序控件可能占用侧边栏宽度 -> 使用短标签和现有工具栏区域，避免影响 TODO 标题可读性。
- 缺失或未知优先级可能导致排序不稳定 -> 统一兜底为 `medium`。
- 缺失或异常 `createdAt` 可能影响同优先级排序 -> 测试常规 `createdAt` 场景，代码中提供确定性兜底。

## Migration Plan

无需数据迁移。现有 TODO 已包含 `createdAt`，旧数据缺少 `priority` 时按 `medium` 参与排序。
