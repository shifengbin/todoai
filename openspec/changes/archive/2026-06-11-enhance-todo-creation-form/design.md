## Context

当前应用是 Wails + Go 后端 + Vue 前端。TODO 工作区已经是主要终端入口，左侧 `TODO` tab 展示 `TODO -> 项目 -> 终端` 树；项目 tab 作为项目库管理入口。现有创建 TODO 逻辑在前端使用 `window.prompt('TODO title')`，后端 `CreateTodo(title string)` 只保存标题。为已有 TODO 添加项目时，前端同样通过 `prompt` 输入项目名并做精确匹配。

本次变更需要把 TODO 创建升级为应用内表单，并让 TODO 数据模型承载描述和优先级。工程选择需要支持搜索，但工程仍然是可选项；未选择工程时，TODO 继续以无关联项目状态创建。

## Goals / Non-Goals

**Goals:**

- 用应用内创建表单替代创建 TODO 的简单弹框。
- 创建 TODO 时保存名称、可选描述和 `高`、`中`、`低` 三档优先级。
- 使用优先级颜色标记选择项和 TODO 行背景。
- 创建 TODO 时可选关联一个或多个工程，并支持按工程名称和路径搜索多选。
- 为已有 TODO 添加工程时也使用可搜索选择交互，移除简单文本弹框。
- 保持旧配置兼容，旧 TODO 加载后获得默认优先级。

**Non-Goals:**

- 不实现 TODO 编辑、重命名或修改优先级。
- 不改变归档恢复策略；归档仍只用于查看历史。
- 不引入新的前端组件库或外部依赖。

## Decisions

### 1. 后端使用创建请求对象

将应用层创建入口从只接收 `title string` 扩展为接收结构化请求，例如 `CreateTodoRequest`，字段包含：

- `title`
- `description`
- `priority`
- `projectIds`

后端负责统一 trim、校验名称、规范化优先级、默认旧值和可选项目关联。若 `projectIds` 非空，创建 TODO 后在同一个持久化流程内创建所有 TODO-项目关联，并把第一个选中工程对应的关联设为当前 TODO 项目上下文。

替代方案是在前端先调用 `CreateTodo` 再调用 `AddProjectToTodo`。这个方案会产生两个状态变更，存在 TODO 创建成功但项目关联失败的半完成状态；用请求对象可以让创建和可选关联成为一个事务式操作。

### 2. 优先级持久化为稳定英文枚举，界面显示中文

后端持久化值使用 `high`、`medium`、`low`。前端显示为 `高`、`中`、`低`，并维护固定颜色映射：

- `high` / `高`: 红色
- `medium` / `中`: 橙色
- `low` / `低`: 绿色

默认优先级为 `medium`。旧 TODO 或缺失优先级字段的数据加载后按 `medium` 处理。

使用英文枚举可以避免后续代码和测试依赖中文文案；中文文案只属于展示层。

### 3. 创建表单放在 App 层，列表渲染留在 ProjectSidebar

`ProjectSidebar` 继续负责左侧树、按钮和 TODO 行展示；点击创建或添加项目时向 `App.vue` 发出事件。`App.vue` 管理 overlay 表单状态、可搜索项目列表、提交和错误展示。

这保持现有数据流：后端状态进入 `App.vue`，再通过 props 传入侧边栏；侧边栏不直接调用 Wails API。

### 4. 搜索选择控件使用本地过滤

工程列表已经在前端状态中，搜索不需要后端 API。过滤规则按项目 `name` 和 `path` 做大小写不敏感包含匹配，并排除已经关联到目标 TODO 的项目。创建新 TODO 时不需要排除项目，因为同一个项目可以关联到多个不同 TODO。

工程是可选项，控件需要提供清空状态。没有工程时提交只创建 TODO；有工程时提交创建 TODO 并关联所有选中工程。创建 TODO 后当前激活工程默认使用用户最先选择的工程。

### 5. TODO 行使用同色系背景而非强饱和填充

TODO 行背景应与优先级颜色一致，但使用浅色背景、边框或左侧色条保证文字可读。活动状态需要与优先级背景叠加后仍可区分，例如保留 active 边框或强调色。

这种方式满足“背景色和优先级一样的颜色”要求，同时避免高优先级红色背景影响长时间使用。

## Risks / Trade-offs

- [Wails 绑定签名变化影响前端调用] → 更新生成的 bindings，并调整前端测试 mock。
- [旧 TODO 缺少 priority/description] → 后端加载和前端展示都提供默认值，避免空字段破坏渲染。
- [创建 TODO 同时关联多个工程导致错误边界更复杂] → 后端先校验 title、priority 和所有 projectIds，再统一保存状态；失败时不写入半完成 TODO。
- [优先级背景影响主题可读性] → 在浅色和深色主题中分别定义同色系 token，测试关键文本可见性。
- [项目搜索列表过长] → 使用本地过滤和滚动区域，保持表单尺寸稳定。

## Migration Plan

1. 扩展 Go 数据结构和加载默认值，旧配置中的 TODO 默认 `priority=medium`、`description=""`。
2. 增加结构化创建请求，并保持应用内部状态保存为同一个 JSON 配置文件。
3. 更新 Wails bindings 和前端调用。
4. 添加创建 TODO overlay、优先级控件和项目搜索选择控件。
5. 更新侧边栏 TODO 行渲染和样式 token。
6. 补充 Go 和前端单元测试，再运行 Go 测试、前端测试和前端 build。

回滚时，旧代码会忽略未知 JSON 字段，但无法理解新的结构化前端调用；回滚应同时回退前后端代码。已写入的 `description` 和 `priority` 字段不会影响旧字段读取。

## Open Questions

无。优先级已确定为 `高`、`中`、`低` 三档。
