## Why

当前创建 TODO 和为 TODO 关联工程都依赖浏览器原生 `prompt`，只能输入简单标题或精确项目名，无法承载描述、优先级和可搜索工程选择等工作流信息。随着 TODO 成为主要终端工作上下文，创建入口需要一次性收集足够的任务信息，并用优先级颜色帮助用户快速扫描任务列表。

## What Changes

- 将创建 TODO 从简单弹框升级为应用内表单。
- 创建 TODO 时支持填写 TODO 名称、可选 TODO 描述和任务优先级。
- 优先级使用 `高`、`中`、`低` 三档，并在选择控件和 TODO 行中使用固定颜色标记。
- TODO 行背景色 SHALL 使用与优先级一致的同色系背景，保证任务优先级在列表中可见。
- 创建 TODO 时工程为可选项且支持多选；未选择工程时，TODO 初始不包含关联项目。
- 工程选择控件支持搜索筛选，可按项目名称和路径查找并选择多个项目。
- 创建 TODO 时若选择工程，系统 SHALL 创建 TODO 并同时建立所有选中 TODO-项目关联。
- 保留现有单独为已有 TODO 添加工程的能力，但其项目选择交互也不应再依赖简单文本弹框。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `todo-workspace`: 修改 TODO 创建要求，增加描述、优先级、颜色标记和可选工程选择；修改 TODO 关联项目选择要求，增加可搜索选择体验。

## Impact

- 后端 TODO 数据模型和持久化 JSON 结构需要增加描述与优先级字段，并保持旧数据默认值兼容。
- 后端创建 TODO API 需要从仅接收标题扩展为接收创建请求，支持可选多项目关联。
- Wails 绑定和前端调用需要同步更新。
- 前端 `App.vue` 需要新增创建 TODO 表单状态、提交逻辑和可搜索多项目选择逻辑。
- 前端 `ProjectSidebar.vue` 需要展示 TODO 描述、优先级标记和同色系背景。
- 相关 Go 测试、前端单元测试和 OpenSpec 规格需要覆盖新增字段、默认值、可选工程和搜索选择行为。
