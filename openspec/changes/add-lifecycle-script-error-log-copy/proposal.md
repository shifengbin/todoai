## Why

生命周期脚本执行失败后，侧栏目前只展示截断后的单行错误摘要，用户无法获取开始 TODO 时初始化脚本或完成 TODO 时完成脚本产生的完整原始输出，排查问题时需要重新运行脚本或转到外部环境复现。失败状态应在当前应用运行期间提供完整日志查看和复制能力，使用户能够直接诊断脚本错误。

## What Changes

- 在初始化脚本或完成脚本执行失败时，除现有错误摘要外，在后端运行时内存中保留该次执行的完整 stdout/stderr 合并输出。
- 在失败状态的 Retry 按钮旁增加复制错误日志按钮，按需获取并复制完整原始输出；没有进程输出时回退复制执行错误信息。
- 支持鼠标悬浮失败状态查看完整错误日志，沿用现有延迟悬浮详情交互，并以保留换行、可滚动的形式展示长日志。
- 在重试、执行成功、TODO 删除、TODO 完成归档或 workspace 切换时清理不再有效的完整错误日志。
- 完整错误日志仅在当前应用运行期间保留，不跨应用重启持久化，也不改变现有截断摘要的状态传输行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `todo-lifecycle-scripts`: 扩展初始化脚本和完成脚本失败状态，允许用户按需查看并复制当前失败执行的完整原始输出。

## Impact

- Go 生命周期脚本执行器需要在失败时暂存完整输出，并提供按 TODO 和阶段查询及清理的运行时接口。
- Wails 应用 API 和生成的前端绑定需要增加完整错误输出的按需读取能力。
- Vue 侧栏失败状态需要增加复制按钮、完整日志悬浮详情及剪贴板失败处理。
- 后端执行器测试、应用 API 测试和前端交互测试需要覆盖完整输出保留、按需读取、复制、悬浮展示及清理行为。
- 不引入新的外部依赖，不改变持久化数据格式。
