## Context

应用是 Wails 桌面应用，Go 后端负责项目候选库、Git 状态和 Git 初始化，Vue 前端负责导入入口、确认交互和状态提示。当前单个导入通过 `CreateProjectFromDialog` / `AddProjectFromPath` 保存所选目录，批量导入通过 `ImportProjectsFromParentDirectory` 遍历父目录下的一级子目录并保存所有可访问目录。

现有 Git 能力已经包含状态查询和 `git init` 执行，但导入流程没有把 Git 仓库作为前置条件。现有规格还要求导入后不立即刷新 Git 状态，因此新的导入判断不能依赖前端导入后再调用状态栏刷新。

## Goals / Non-Goals

**Goals:**

- 单个项目导入只基于用户选择的目录判断是否为 Git 仓库。
- 单个非 Git 目录导入时，先让用户确认是否初始化 Git 仓库；确认后初始化并导入，拒绝后不导入。
- 拒绝初始化时显示独立 toast，2 秒后自动消失。
- 批量导入只扫描父目录下一级子目录，并只导入一级 Git 仓库子目录。
- 批量导入按钮提供 hover 提示，说明仅导入一级子目录中的 Git 仓库。
- 保持导入后不立即刷新 active project Git 状态的既有行为。

**Non-Goals:**

- 不递归扫描多级子目录。
- 不在批量导入中为非 Git 子目录逐个弹窗或自动初始化。
- 不配置远程仓库、默认分支、初始提交或 `.gitignore`。
- 不改变 TODO project copy、终端启动和 Git 状态栏的既有职责边界。

## Decisions

1. **将 Git 仓库判定作为导入前置条件，而不是导入后状态栏检查。**

   后端应提供可复用的“路径是否为 Git 仓库”判断，单个导入和批量导入都使用它。这样可以满足导入阶段拦截普通目录，同时避免违反“导入后不立即刷新 Git 状态”的既有约束。

   备选方案是前端导入后调用 `GetProjectGitStatus` 再决定是否保留项目。该方案会产生短暂错误记录、额外状态刷新，并与现有规格冲突。

2. **单个非 Git 导入的确认由前端发起，初始化由后端执行。**

   前端在用户选择单个目录后获得明确的导入结果：已导入、需要初始化、已取消或失败。遇到需要初始化时，前端显示确认交互；用户确认后调用后端在同一路径执行 Git 初始化并导入。用户拒绝时前端不导入，并显示 2 秒 toast。

   备选方案是在后端或系统对话框内直接处理确认，但 Wails 后端不应持有 UI 决策，前端也更适合管理 toast 生命周期和测试。

3. **批量导入只接受一级子目录自身为 Git 仓库。**

   批量入口选择的是父目录，系统只检查父目录下直接子目录，不递归。每个子目录必须自身是 Git 仓库根或 worktree 才导入；普通文件、不可访问目录、重复路径和非 Git 子目录都计入跳过。

   备选方案是使用 `git status` 判断子目录是否处于任意父级 Git 工作树中。该方案会把 monorepo 内普通一级目录误认为可导入项目，不符合“一级子目录本身是项目”的批量导入语义。

4. **toast 独立于现有状态栏错误。**

   现有 `errorMessage` 是状态栏内的持久错误展示。拒绝初始化不是系统错误，应使用独立 toast 状态，默认 2 秒自动清除，避免覆盖真实错误或持续占用状态栏。

## Risks / Trade-offs

- **Git 仓库判断边界不清** -> 通过检查目录自身的 `.git` 目录或 `.git` 文件覆盖普通仓库、submodule 和 worktree，避免把父仓库内普通子目录当作项目仓库。
- **Git 未安装时单个初始化失败** -> 后端沿用现有 Git 初始化错误，前端显示非阻断错误；用户拒绝初始化时不触发后端 Git 命令。
- **批量导入跳过过多目录让用户困惑** -> 批量按钮 hover 提前说明规则，导入摘要继续展示 imported/skipped 数量。
- **toast 定时器泄漏或覆盖** -> 前端保存 toast timer，显示新 toast 前清理旧 timer，组件卸载时清理。

## Migration Plan

不需要数据迁移。该变更只影响新增导入行为；已有全局候选项目和 TODO project copy 保持原样。回滚时移除新增导入检查、确认交互和 toast，并恢复父目录批量导入所有可访问一级子目录的行为。

## Open Questions

无。用户已明确单个导入只判断所选目录，批量导入只判断父目录下一级子目录。
