## Why

当前项目导入会把普通目录也加入全局项目候选库，用户后续进入 TODO 工程上下文时才发现目录不是 Git 仓库，体验不够明确。导入阶段应把“项目候选必须是 Git 仓库”的规则前置，并在单个非 Git 目录导入时给用户一次初始化后继续导入的机会。

## What Changes

- 单个项目导入只判断用户选择的目录本身是否为 Git 仓库。
- 单个项目导入遇到非 Git 目录时，提示用户是否初始化 Git 仓库后导入。
- 用户同意初始化时，系统在所选目录执行 Git 初始化，成功后导入该目录。
- 用户拒绝初始化时，系统不导入该目录，并显示 2 秒后自动消失的 toast，提示只能导入 Git 仓库。
- 批量导入只扫描用户选择父目录下的一级子目录，并且只导入其中已是 Git 仓库的子目录。
- 批量导入自动跳过非 Git 子目录，导入摘要继续显示导入和跳过数量。
- 批量导入按钮 hover 时提示仅导入一级子目录中的 Git 仓库。

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `global-project-candidates`: 修改全局项目候选导入规则，要求导入目标为 Git 仓库，并定义单个非 Git 导入的初始化确认和 toast 提示行为。
- `project-workspace`: 修改父目录批量导入规则，只导入一级 Git 仓库子目录，并提示批量导入仅支持 Git 仓库。

## Impact

- Go 后端项目导入流程：单个导入需要判断 Git 仓库并支持确认后的初始化导入；批量导入需要过滤非 Git 一级子目录。
- Wails API：可能需要新增或调整单个导入流程所需的 Git 仓库检测和初始化调用边界。
- Vue 前端导入交互：需要增加单个非 Git 导入确认、拒绝后的 toast、批量导入按钮 hover 提示。
- 测试：需要覆盖单个非 Git 导入确认/拒绝、批量跳过非 Git 子目录、toast 自动消失和按钮提示。
